# Styles

Components use `cn-*` placeholder classes for their visual styling. A style maps each placeholder to Tailwind classes, the same way shadcn/ui does. Fulldev UI supports all shadcn/ui styles: vega, nova, maia, lyra, mira, luma, sera, and rhea.

- `shadcn/style-<name>.css`: unmodified copies of the shadcn/ui style files, under the shadcn/ui MIT license in `shadcn/LICENSE.md`. Copied from [shadcn-ui/ui](https://github.com/shadcn-ui/ui/tree/main/apps/v4/registry/styles) at commit `295a1f1`. Do not edit them; copy a newer version instead and run `pnpm registry:build`.
- `shadcn/themes.json` and `shadcn/fonts.json`: the shadcn/ui theme colors and font definitions, copied from the same commit for the docs create page.
- `adapted/style-<name>.css`: `cn-fd-*` placeholders, generated by `scripts/registry-adapt.mjs`. They copy a shadcn/ui placeholder and rewrite its selectors for components whose markup exposes state differently than Base UI, such as `data-highlighted` instead of `focus` in menus. Do not edit or format them: Prettier would reorder their classes, which changes how conflicting classes merge, and the docs previews would no longer match installs. `pnpm test` checks that they match.
- `fulldev/style-<name>.css`: placeholders for Fulldev UI components that shadcn/ui does not have, such as banner, header, section, and typography. Vega keeps the original Fulldev UI classes; the other styles follow how shadcn/ui treats comparable components.

## Rules

- Use a shadcn/ui placeholder with the same name when a component matches shadcn/ui. Keep structural classes (layout, positioning, behavior) in the component and visual classes (radius, color, density, type) in the placeholder.
- A placeholder only goes in a quoted class string, before the other classes in that string. The build replaces placeholders in every quoted string that contains one.
- A placeholder that a style does not define is removed for that style. A placeholder that no style defines fails the build.

## Build

`pnpm registry:build` regenerates `adapted/`, builds the registry, and writes the output once per style to `public/r/styles/base-<name>/`. `public/r/{name}.json` stays the vega output for existing installs.

The docs site renders placeholders with the same code (`scripts/styles.mjs`): `src/middleware.ts` renders pages in vega, and each live preview is rendered once per style for the style menu. Tailwind reads the style files through `@source` in `src/styles/global.css`. Restart `pnpm dev` after changing a style file.
